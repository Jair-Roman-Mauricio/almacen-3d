## Concurrencia, cantidades y fechas

Las carreras observan bloqueos reales con `pg_blocking_pids` antes de liberar
al competidor. Se usan conexiones distintas; no se reemplaza PostgreSQL por mocks
ni se presenta una secuencia de solicitudes como simultaneidad.

- Layout: barrera exclusiva por almacén y revisión comprobada dentro de ella.
  `LAYOUT_STALE` devuelve `error.details[].currentRevision` como cadena exacta.
- Stock/trabajo: barrera compartida del almacén, filas de ubicaciones, productos
  y posiciones en orden único. Después de la espera se releen ámbito y bloqueo.
- Dos movimientos por la última unidad dejan una confirmación y un rechazo;
  dos orígenes hacia un saldo destino inicialmente ausente conservan la suma.
- Las cantidades permanecen en BigInt/numeric. Se confirma y reconcilia
  `9007199254740993.125`, sin pasar por números binarios de JavaScript.
- Las líneas repetidas se agregan antes de validar disponibilidad. Los movimientos
  registran ambas piernas físicas y conservan reservas. Cada cambio físico
  efectivo incrementa la revisión, incluso si una operación toca ambos sentidos.
- La prueba de respuesta perdida cierra realmente el socket al enviar el JSON
  después del commit; una nueva API consulta y recupera esa misma confirmación.
- El historial usa el intervalo UTC semiabierto calculado en la zona de empresa.
  El 08/03/2026 en America/New_York tiene 23 horas: se comprueban ambos bordes y
  se ignora una zona de cliente distinta indicada en la petición. El QA de la
  presentación de fechas en navegador pertenece a las futuras pantallas.

## Decisiones internas dentro del plan

- La API comparte el borde de sesión, roles actuales y comando con los módulos
  `warehouses`, `catalogue` e `inventory`; Nest mantiene una única instancia del
  servicio de identidad por aplicación.
- La retirada física es lógica internamente (`layout_elements.removed_at`):
  desaparece del layout activo conservando stock vacío y claves históricas.
  Se comprueba stock/trabajo de todos los descendientes antes de permitirla.
  Un UUID persistido no cambia de almacén/tipo ni se revive como otro elemento.
- El código solo es único entre elementos activos del mismo tipo/almacén. Se
  pueden intercambiar códigos dentro de una transacción y reutilizar el de un
  elemento retirado con un UUID nuevo, preservando la identidad anterior.
- Las comprobaciones de trabajo pendiente incluyen reservas/preparación,
  orígenes de traslados sin salida y conteos todavía no ajustados. Su creación
  HTTP corresponde a fases posteriores; aquí se preparan fixtures relacionales
  válidas y se usa el protocolo de transacción compartido.
- El cliente no altera bloqueos con el guardado geométrico. Bloquear/desbloquear
  no ejecuta trabajo pendiente ni modifica cantidades o revisiones físicas.
- Revisiones de layout viajan como cadenas enteras; `baseRevision` acepta una
  cadena entera o un número entero seguro. No se pierde precisión de bigint.
- GET layout admite gzip con `Accept-Encoding`. El límite técnico JSON inicial
  es 16 MiB, configurable con `API_JSON_LIMIT`; no es un límite de elementos ni
  una cuota comercial. Se preserva el contrato 400/413 de entrada.
- Consultas con cursores ligados a empresa, recurso y filtros; historial también
  liga la zona de empresa. Las respuestas operativas usan `no-store`.

Seguir [desarrollo](../desarrollo.md) y ejecutar:

```sh
node scripts/pnpm-local.mjs install --frozen-lockfile
node scripts/pnpm-local.mjs run lint
node scripts/pnpm-local.mjs run test:unit
node scripts/pnpm-local.mjs run test:integration
node scripts/pnpm-local.mjs run typecheck
node scripts/pnpm-local.mjs run build
node scripts/pnpm-local.mjs run db:migrate
node scripts/pnpm-local.mjs run db:migrate --test
```

Los errores internos de las pruebas con fallos de almacenamiento inyectados son
esperados: sus asserts verifican 500 y rollback. No son fallos de la suite.

## Límites

Este bloque implementa backend HTTP. No adelanta UI, editor/visor visual,
pedidos, picking, despachos, traslados/conteos HTTP, parser, SSE ni landing.
La comprobación de 1.000 ubicaciones no certifica el perfil grande de 20.000,
latencias, carga concurrente, restauración o equivalencia completa de modos.
Esas mediciones y flujos conservan sus tareas pendientes. No hay despliegue,
release ni cobro real. Siguiente tarea: **T073**.
