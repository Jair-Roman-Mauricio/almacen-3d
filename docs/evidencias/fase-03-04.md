## Evidencia de concurrencia y recuperación

Las carreras usan conexiones reales y barreras controladas, observando
`pg_blocking_pids` antes de liberar al competidor. No se sustituyen por mocks ni
se deduce una carrera a partir de un simple `Promise.all` sin observar espera.

- Barrera de permisos compartida para acciones, exclusiva para cambios de rol,
  desactivación y logout; comprobación del estado después de adquirirla.
- Referencia por empresa serializada antes de leer/aplicar; un replay devuelve
  resultado y fecha originales. Una referencia nueva sigue siendo otra acción.
- Registro duplicado: la segunda solicitud espera al primer alta y recibe 409;
  conserva una sola pareja empresa/administrador.
- Setup local: exclusión de instalación, empresa/admin/estado en una transacción;
  reiniciar la API contra la misma base no vuelve a habilitarlo.
- Último administrador: el segundo cambio espera al primero y recibe
  `LAST_ACTIVE_ADMIN`; permanece un administrador activo.
- Las fixtures esperan el cierre de sus conexiones antes de borrar la base
  privada. No terminan forzosamente clientes que aún están cerrándose.

## Implementación y decisiones dentro del plan

- `packages/database/src/unit-of-work.ts`: protocolo compartido de bloqueos.
  `withTransaction` rechaza transacciones independientes anidadas y transforma
  conflictos transitorios de PostgreSQL en un resultado recuperable 503.
- `apps/api/src/platform/commands`: canonización, SHA-256 de datos de negocio y
  ejecución atómica. `0012` impide reescribir una confirmación persistida.
- `packages/database/src/audit.ts`: asientos, auditoría y outbox ligados al sello
  del comando. No publica todavía eventos SSE.
- `0013–0016`: funciones limitadas de autenticación/provisión, con
  `SECURITY DEFINER`, nombres cualificados, `search_path` fijo y sin EXECUTE
  público. El proceso normal no usa credenciales de migración/bootstrap.
- Argon2id 0.45.1, previsto en el plan, usa memoria 64 MiB, tres iteraciones,
  paralelismo 1 y sal aleatoria. No se cambia ni recorta la contraseña.
- Token de sesión aleatorio de 256 bits, solo SHA-256 en PostgreSQL; CSRF se
  deriva con HMAC del token opaco. La cookie es HttpOnly, SameSite=Lax y Secure
  bajo HTTPS. No se añade una caducidad comercial no especificada.
- Al crear una cuenta, la contraseña queda fuera de la huella rápida y de la
  auditoría. El replay valida la contraseña contra el Argon2id de la cuenta
  original: una contraseña distinta entra en conflicto sin crear otra cuenta.
- La lista de equipo tiene cursor ligado a empresa/filtro, orden estable por UUID
  y página predeterminada de 50. Campos y filtros desconocidos se rechazan.
- La consulta de resultados usa una política explícita por tipo de comando;
  tipos aún desconocidos se deniegan. Los módulos siguientes deberán registrar
  su permiso al implementar cada tipo. El caso pendiente usa staging sintético:
  no acredita el parser ni el procesamiento de importaciones.

RF asociados: los indicados literalmente en T032–T052 de `tasks.md`, con las
comprobaciones I-INV/orden-bloqueos, I-CMD, I-AUD, I-SET, I-ACC e I-ISO de este
bloque. Los RF transversales continuarán comprobándose en los módulos posteriores;
esta entrega no certifica todas las rutas futuras del WMS.

## Reproducción

Preparar las bases según [desarrollo](../desarrollo.md) y ejecutar:

```sh
node scripts/pnpm-local.mjs install --frozen-lockfile
node scripts/pnpm-local.mjs run lint
node scripts/pnpm-local.mjs run test:unit
node scripts/pnpm-local.mjs run test:integration
node scripts/pnpm-local.mjs run typecheck
node scripts/pnpm-local.mjs run build
node scripts/pnpm-local.mjs run db:migrate
node scripts/pnpm-local.mjs run db:migrate --test
```

Las pruebas de fallo deliberado emiten dos mensajes internos con requestId; son
casos esperados con rollback comprobado, no fallos de la suite.
