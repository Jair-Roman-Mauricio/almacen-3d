## Decisiones técnicas y hallazgos corregidos

El staging conserva bytes originales para recuperar parsing y filas normalizadas
para validar/aplicar sin confiar en datos devueltos por el navegador. La huella
incluye clase, almacén y contenido normalizado. La intención se serializa por
referencia; el trabajador verifica autor administrador actual y continúa esa misma
referencia. Catálogo serializa SKU antes de bloquear productos; stock inicial
bloquea almacén, ubicaciones, productos y saldos, y vuelve a validar antes de escribir.
Un fallo guarda la explicación del job después del rollback; no inventa un resultado
confirmado ni permite volver a aplicar el mismo trabajo con otra referencia.

El trabajador se inicia al detectar pendientes y recupera la cola al arrancar la
API. La prueba de reinicio interrumpe un hilo Node mientras PostgreSQL espera un
lock sintético, comprueba rollback y arranca otro trabajador. Tras commit, dos
replays recuperan exactamente el mismo resultado; se verifica un único efecto.

ExcelJS 4.4.0 podía leer una hoja antes de su modelo según el orden de miembros ZIP.
`xlsx-container` presenta los metadatos antes de las hojas conservando los bytes
comprimidos; la lectura de filas sigue siendo incremental. Se añadieron regresiones
para archivos pequeños, 20.000 filas, fórmulas, enlaces por rango y macros.
CSV rechaza caracteres nulos antes de staging para no dejar un trabajo reintentando
un valor que PostgreSQL no puede representar. Su regresión falló antes de la corrección.
Los límites inclusivos se comprobaron también desde multipart HTTP; no se dedujo
su aceptación únicamente de una constante del parser.

Las filas de cada descarga salen de una sola sentencia MVCC y la zona permanece
estable durante la lectura. Se exportan todas las coincidencias de los filtros,
incluso si la consulta original estaba paginada. Los cursores se validan con el mismo
ámbito/zona del historial. CSV escapa celdas y neutraliza texto con prefijos de fórmula;
XLSX guarda strings explícitos, incluidos enteros mayores que Number.MAX_SAFE_INTEGER.
Las plantillas XLSX solo incluyen Datos para poder importarse; las descargas incluyen Consulta.

El publicador usa una conexión técnica y exclusión PostgreSQL; consulta siempre
pendientes, no un máximo de secuencia. Emite antes de marcar publicado, por lo que
una interrupción puede repetir un aviso, sin repetir inventario. Cada envío SSE
revalida sesión bajo la barrera de permisos. Solo se transmiten ámbitos/IDs; los
valores autoritativos siguen en REST. Los streams no reservan una conexión de datos.
`ready` solicita refrescar consultas al reconectar; la invalidación visual sigue en T129.
La entrega comprobada usa una instancia API local; no acredita distribución de streams
entre varios procesos API ni latencia visible de una UI todavía no implementada.

El seed requiere DEMO_MODE explícito y una base vacía o marcada previamente como
demo. Provisión registra cuentas ficticias; operaciones normales generan su libro
con referencias deterministas. SaaS tiene dos empresas y seis cuentas; local una
empresa/tres cuentas y setup cerrado. El manifiesto público usa claves demo y
credenciales ficticias estáticas, sin consultar contraseñas de cuentas reales.
El comando real `pnpm run db:seed:demo` se ejecutó dos veces sobre una base privada:
14 asientos antes/después, sin duplicados. Ver [guía](../desarrollo.md#demostración-explícita).

Dos errores de fixture se corrigieron sin relajar resultados: uso incorrecto de
IDs de una escena al comenzar T096 y ordenación textual de una cantidad convertida
a texto en T106 (se ordena por la columna numeric). Se esperó liberación efectiva
del pool en SSE antes de comprobarla; los escenarios largos con varias conexiones
usan timeout explícito de prueba. No se cambian umbrales de rendimiento del acuerdo.
El recuento de RLS se amplió de 23 a 24 y comprueba expresamente la tabla demo nueva.


El build de Next conserva únicamente `/health` y la página técnica no encontrada.
No se mantiene un servidor público ni se configura un servicio cloud. Las pruebas
inyectan fallos deliberados que generan errores HTTP esperados, con mensajes de
registro sanitizados; el resultado real de la suite termina en cero fallidas.

Los límites de archivos se verificaron funcionalmente; los objetivos RNF-13–16
sobre perfil grande, 50 sesiones, commit→valor visible, 3D y procesamiento acumulado
se medirán en T194–T204. No se atribuyen esas capacidades a este cierre.
